# Виртуальная смена ВСМ

Учебная игра для проводников: две ситуации, решения под ограничением времени, разбор ошибок и сохранение результатов. Для работы игры внешние сервисы ИИ не нужны.

После смены можно нажать «Отработать ошибку». Три коротких упражнения подбираются по невыполненным пунктам. Они сохраняются отдельно, не приносят баллов и не заменяют самостоятельную проверку. Подробности — в `docs/practice.md`.

Демонстрация: https://185.173.147.205/. [Ответы для формы сдачи](docs/submission.md), [путь игрока](docs/user-flow.md), [проверка по тест-кейсам](docs/customer-test-report.md), [развёртывание на Linux](docs/deployment.md).

## Запуск

Нужен запущенный Docker Desktop в режиме Linux-контейнеров. На Windows используйте **PowerShell 7.6.6**: на этой версии команда подтвердила успешный запуск. Совместимость с Windows PowerShell 5.1 не заявлена. PHP и Node.js отдельно устанавливать не нужно; запуск выполняется командами Docker без файлов `.ps1`.

Откройте PowerShell 7 и проверьте версию:

```powershell
$PSVersionTable.PSVersion
```

Если отображается 5.1, открыт Windows PowerShell. В меню «Пуск» выберите PowerShell 7.

Если проект ещё не скачан, выполните по очереди:

```powershell
git clone https://github.com/proger89/test123334.git
cd test123334
```

Если скачали ZIP, распакуйте его и откройте терминал в папке, где лежит `compose.yaml`. Следующие команды вводите по одной, дожидаясь завершения каждой. При ошибке остановитесь и проверьте сообщение.

**1. Создайте настройки.** Docker сам создаст `.env` со случайными ключами и паролями. При повторном запуске существующий файл сохраняется.

```powershell
docker compose -f compose.setup.yaml run --rm setup
```

**2. Загрузите образ базы.** Дождитесь успешного завершения команды перед сборкой приложения.

```powershell
docker compose pull db
```

**3. Соберите приложение.** При первой сборке нужен интернет; загрузка зависимостей может занять несколько минут.

```powershell
docker compose build api web
```

**4. Запустите игру.** Команда использует уже собранные образы и дождётся базы, подготовки сценариев и готовности приложения.

```powershell
docker compose up --no-build -d --wait web worker
```

**5. Откройте http://127.0.0.1:8180 в браузере.** Если сайт не открылся, посмотрите состояние и последние сообщения:

```powershell
docker compose ps -a
docker compose logs --tail 50 init api worker web
```

Для остановки:

```powershell
docker compose stop
```

Для следующего запуска:

```powershell
docker compose up --no-build -d --wait web worker
```

Результаты сохраняются в томе базы. Не удаляйте `.env` и не используйте `down -v`: это может лишить доступа к сохранённым данным. Файл `.env` содержит секреты, его не нужно отправлять другим участникам или добавлять в Git. Если порт 8180 занят, остановите приложение, которое его использует.

После обновления кода повторите команды сборки и запуска. Для уже клонированного репозитория без своих изменений обновление выполняется командой `git pull --ff-only`.

### Если Docker пишет `No such image: postgres:17-alpine@sha256:...`

Это ошибка поиска образа базы на компьютере. Сначала отдельно загрузите именно образ из настроек проекта, затем повторите запуск без сборки:

```powershell
docker compose pull db
docker compose up --no-build -d --wait web worker
```

Если первая команда завершилась с ошибкой, не переходите ко второй. Если обе команды снова приводят к `No such image`, перезапустите Docker Desktop и повторите их. Не удаляйте тома, `.env` и не заменяйте версию PostgreSQL. Для разбора повторного сбоя сохраните полный вывод этих двух команд и версий:

```powershell
docker version
docker compose version
```

Указанный в проекте образ проверен в реестре Docker 26 сентября 2026 года. Загрузка отдельно от сборки и запуск проверены локально. Причина сбоя на другом компьютере без его журналов не подтверждена.

## Проверки и разработка

Серверные тесты работают в отдельном проекте с отдельной базой:

```powershell
docker compose build api
docker compose -p vsm-hackathon-test -f compose.test.yaml run --rm tests
docker compose -p vsm-hackathon-test -f compose.test.yaml stop
```

Для разработки с обновлением интерфейса после сохранения файлов:

```powershell
docker compose -f compose.yaml -f compose.dev.yaml up --build -d --wait web worker frontend-dev
```

Перед возвращением к обычной сборке остановите службы разработки, затем выполните шаги 3 и 4:

```powershell
docker compose -f compose.yaml -f compose.dev.yaml stop
```

Браузерные проверки используют отдельное приложение на 8181. Нужны Node.js 24 и установленный Microsoft Edge (либо задайте `BROWSER_CHANNEL=chrome`). Данные основного приложения при этих проверках не меняются:

```powershell
docker compose -p vsm-hackathon-acceptance -f compose.yaml -f compose.acceptance.yaml up -d --wait web worker
npm --prefix client ci
npx --prefix client playwright test --config client/playwright.config.ts
# Дополнительные проверки HTTP, сроков и перезапуска: Python 3.11+
python scripts/http_acceptance.py
docker compose -p vsm-hackathon-acceptance -f compose.yaml -f compose.acceptance.yaml stop
```

Повторный запуск проверок создаёт новые тестовые профили в отдельной базе. Скрипт HTTP-проверки останавливает и перезапускает только проект `vsm-hackathon-acceptance`. Полный прогон занимает несколько минут, в том числе ожидание реальных сроков. Отчёты сохраняются в `tmp/`.

## Как играть

Выберите смену и режим. Обучение позволяет пользоваться подсказкой и паузой; баллы рейтинга начисляются только за зачтённые проверки. Первая смена объединяет неисправность розетки и багаж в проходе. Второе обращение появляется через 20 секунд после первого ответа. После его появления есть 45 секунд на освобождение прохода. Во второй смене за 35 секунд нужно сообщить о багаже без владельца. Эти сроки — настройки учебной модели.

Первый пункт задания организаторов требует создания и ведения игрового профиля с прогрессом, уровнем и очками; отдельная регистрация по логину и паролю не указана. В этой версии используется гостевой профиль, а вход в учётную запись сотрудника запланирован после хакатона.

Профиль создаётся автоматически, вместо имени можно указать псевдоним. Данные хранятся на сервере, доступ привязан к сессии браузера. Удаление данных сайта или 30 дней без входа приводят к потере доступа к гостевому профилю.

## Проверка работы

```powershell
docker compose ps
docker compose logs --tail 50 api worker init
docker compose exec api php artisan scenario:publish /var/www/content/new-version.json
docker compose exec api php artisan demo:bonus-expiry НОМЕР_ПРОФИЛЯ
docker compose exec api php artisan integration:token
```

Последняя команда выдаёт ключ чтения результатов на 24 часа. Не размещайте его в браузерном коде или Git. Номер своего профиля виден на экране «Профиль». Демонстрационный бонус действует 90 секунд, предупреждение появляется за 60 секунд до окончания.

## Редактор сценариев

Откройте пункт **«Редактор»** или адрес `/#editor`. Код методиста хранится в `EDITOR_ACCESS_CODE` в локальном `.env`; первая команда Docker создаёт его один раз. Не публикуйте код и не добавляйте `.env` в Git. На сервере свой `.env`; при необходимости владелец может задать такой же код, как локально.

Выберите исходную версию → «Создать черновик» → измените шаги и действия → «Сохранить черновик» → «Попробовать» → «Опубликовать». Новая версия доступна только в обучении. Подробности, ограничения и контракт: [docs/editor.md](docs/editor.md). Черновики привязаны к профилю браузера. Код даёт доступ на 8 часов; выход закрывает его сразу.

Для повторной проверки редактора используйте отдельное приложение на 8181 по инструкции выше. Браузерные тесты читают код из локального `.env` и не выводят его в отчёт. Публикации при тестировании происходят только в отдельной базе.


Проверка замечаний к ТЗ 4.0: [что исправлено и как проверить](docs/qa-feedback-2026-09-26.md). Для ускоренной проверки временной награды запустите проект локально, откройте «Прогресс» и раскройте «Ускоренная демонстрация временных баллов». Кнопка выдаёт 20 баллов на 90 секунд один раз на профиль; повторное нажатие ничего не продлевает. На публичном сервере этой возможности нет.
