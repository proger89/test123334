# Проверка разбора смены и запуска упражнения

26 сентября 2026 года.

Причина сообщения «Отработать ошибку не работает»: сервер правильно отклонял второй запуск с кодом `409 active_attempt`, но интерфейс помещал сообщение над разбором, вне видимой части длинной страницы. При переходе из другого раздела сообщение также могло очищаться эффектом смены страницы.

Исправления:

- Ответ об активном прохождении содержит его идентификатор. Он выбирается только среди попыток текущего профиля под общей блокировкой. Повтор запроса сохраняет прежний ответ.
- Окно «Есть незавершённое прохождение» видно независимо от прокрутки. Оно позволяет продолжить сохранённую попытку или остаться на текущей странице. Клавиша Escape закрывает окно и возвращает фокус на исходную кнопку.
- Переход в упражнение происходит после успешного ответа. Остальные ошибки прокручиваются в видимую область и получают фокус.
- Кнопки завершения смены и упражнения красные, с белым текстом.
- Разбор показывает сначала выполненные пункты, затем пункты для повторения и упражнения. Оценки по навыкам и последствия доступны в раскрываемых разделах. Итоговая оценка и критическая ошибка остаются видны сразу.
- При возвращении после истечения срока обновляется и история результатов. Правила игры, очки и сохранённые попытки не менялись; миграций базы нет.

Проверки на отдельной базе:

- 53 серверных теста, 429 проверок: защита владельца, идентификатор незавершённой попытки, повтор запроса и прежние игровые правила.
- 17 браузерных тестов: оба сценария, упражнения, паузы и реальные сроки, сохранение, награды, рейтинг, потеря связи, новый разбор на ширинах 390 и 1366, игра также на 768, возврат к приостановленному упражнению и запуск следующего после завершения.
- TypeScript и сборка интерфейса прошли. Снимки экрана проверены на читаемость и отсутствие горизонтальной прокрутки.

Первый прогон обнаружил потерю фокуса после закрытия окна; она исправлена сохранением исходной кнопки до отправки запроса. Старая база приёмки также содержала изменённую учебную версию после прежних тестов редактора, поэтому итоговый прогон выполнен на новом отдельном проекте `vsm-hackathon-ui-review`. Старые данные и тома сохранены. Тест истории уточнён: он выбирает проверку, а не первую строку, которая могла относиться к обучению.

Журналы: [сервер](evidence/results-server-tests.txt), [браузер](evidence/results-browser-tests.txt). Подготовка комплекта: `python scripts/prepare-submission.py` после фиксации изменений в Git. Архив содержит только файлы выбранного коммита; скрипт проверяет целостность, исключённые каталоги и отсутствие локальных секретов.
## Запуск без PowerShell-скриптов

По замечанию участницы добавлена последовательность обычных команд Docker в README. Создание `.env` выполняется отдельным контейнером из закреплённого официального образа PHP; PHP на компьютере не нужен. Повторная подготовка не меняет существующие настройки. Проверены создание нового файла и совпадение контрольной суммы при повторном запуске, затем сборка и запуск основного приложения командами из Windows PowerShell 5.1. На этом стенде все четыре постоянные службы на 8180 были здоровы. Эта локальная проверка не подтвердила совместимость со всеми рабочими местами: на компьютере участницы запуск в Windows PowerShell 5.1 не удался, а в PowerShell 7.6.6 прошёл. Причина различия не установлена. В инструкции для команды теперь указана PowerShell 7.6.6.

Первое требование оригинального задания — создание и ведение игрового профиля. Регистрация по логину и паролю отдельно не требуется. В демонстрации профиль гостевой; ограничение переноса и восстановления доступа явно описано в README и форме сдачи. TC001 не объявляется буквальным совпадением с присланными шагами.

## Дополнительная проверка профиля и сборки

По вопросу о вводе проверены строки с SQL и HTML: имя сохраняется как значение, число профилей не меняется; HTML показывается текстом, не создаёт элемент изображения и не вызывает окно JavaScript. Длина 2–40 проверяется сервером, в браузере установлен максимум 40. Дополнительный браузерный тест пройден: `profile-security.spec.ts`, журнал `evidence/profile-browser-tests.txt`. Это проверка конкретного поля, а не заявление о полном аудите безопасности.

Первый прогон на публичном сайте обнаружил ошибку доступа к `AttemptService.php`: ограничительная маска прав процесса развёртывания сохранила новый файл доступным только владельцу root, а PHP работает от www-data. Доступ восстановлен; Dockerfile теперь явно задаёт владельца кода и сценариев при копировании в образ. Это устраняет зависимость от владельца и маски прав исходных файлов. Данные и секреты не изменены.
