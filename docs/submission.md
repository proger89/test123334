## Описание архитектуры решения

Браузерный интерфейс написан на React и TypeScript. Nginx отдаёт интерфейс и направляет запросы в Laravel API. Серверный игровой движок рассчитывает переходы между шагами, сроки, последствия и итоговую оценку. PostgreSQL хранит профили, версии сценариев, попытки, прогресс и награды. Отдельный обработчик проверяет сроки и создаёт уведомления. Все компоненты запускаются в Docker Compose.

Содержание сценария задаётся в JSON: условия, реплики, действия, последствия, сроки, критерии и источники. Игровой движок исполняет только предусмотренные операции. Проверка времени и начисления выполняются на сервере; повтор одного запроса не повторяет действие. Начатое прохождение сохраняет свою версию сценария. Короткие упражнения подбираются по невыполненным пунктам, сохраняются отдельно и не изменяют рейтинговые результаты.

Редактор доступен в отдельном разделе по коду методиста. Он позволяет менять шаги, реплики, условия, последствия и сроки, проверять переходы и проходить черновик перед публикацией. Новая версия используется только в обучении; начатые попытки и рейтинговые проверки сохраняют прежние правила. Инструкция: https://github.com/proger89/test123334/blob/main/docs/editor.md

Диаграммы компонентов и обработки запроса: https://github.com/proger89/test123334/blob/main/docs/architecture.md

## Описание API и пользовательского сценария

OpenAPI: https://github.com/proger89/test123334/blob/main/docs/openapi.json

Путь игрока и примеры двух смен: https://github.com/proger89/test123334/blob/main/docs/user-flow.md

API `/api/v1` включает профиль, сценарии, попытки, действия, паузу, результаты, упражнения, прогресс, рейтинги, уведомления и испытание. Изменяющие запросы защищены CSRF; доступ к попытке проверяется по профилю. Команды содержат идентификатор запроса и ожидаемую ревизию. Экспорт результатов доступен только на чтение по отдельному ограниченному ключу. Реальные системы заказчика не подключены.

Игрок выбирает обучение или проверку, принимает решения и видит их последствия. В первой смене нужно одновременно помочь с неисправной розеткой и освободить проход от багажа. Во второй — выбрать действия при обнаружении вещи без владельца. Разбор показывает каждое решение, объяснение и источник. При ошибке можно выполнить короткое упражнение в изменённых обстоятельствах, затем пройти самостоятельную проверку. Прогресс показывает фактические результаты, навыки, достижения и часто невыполненные пункты.

## Ограничения и план развития после хакатона

В демонстрации две полные смены и три коротких упражнения. Бригады, депо и готовые примеры в рейтинге вымышлены. Профиль гостевой, привязан к браузеру; восстановление доступа после удаления данных сайта не предусмотрено. Публичный стенд использует HTTP и предназначен для демонстрации с псевдонимами. Для рабочего использования нужны домен, HTTPS, учётные записи и согласованные правила хранения данных.

Рабочие решения основаны на предоставленных материалах. Сроки, штрафы и допустимый порядок отдельных действий — учебные настройки. Полный регламент транспортной безопасности не предоставлен; перед использованием для подготовки персонала содержание должен подтвердить заказчик. Тренажёр не является профессиональной аттестацией. Улучшение навыков пока не измерялось на сотрудниках.

Следующие шаги: согласовать содержание с методистами; добавить персональные роли методистов и согласование новых версий сценариев; подключить кадровую систему и систему обучения; провести проверку на группе сотрудников и оценить повторяемость ошибок до и после обучения. ИИ можно рассмотреть для подготовки черновиков реплик с обязательным согласованием. В текущей игре решения, объяснения и оценки определяются проверяемыми правилами, без внешних моделей.
