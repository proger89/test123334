# Редактор сценариев

План реализации и проверка границ: 25 сентября 2026 года.

Раздел «Редактор» предназначен для методиста. Доступ открывается отдельным кодом на восемь часов; обычный гостевой профиль не даёт прав на чтение черновиков или публикацию. Код хранится вне Git, попытки входа ограничены, изменения защищены CSRF. Черновики принадлежат создавшему их профилю. Общий код подходит для демонстрации; персональные учётные записи методистов остаются следующим этапом.

1. Скопировать одну из опубликованных версий двух смен в свой черновик.
2. Изменить название, условия, сроки, шаги, варианты действий, переходы, последствия, объяснения и источники через поля формы.
3. Сохранить черновик. Ошибки содержания не мешают сохранению, но блокируют пробу и публикацию.
4. Проверить структуру, ссылки между шагами и наличие выхода из достижимых состояний. Проба использует тот же движок, отдельное сохранённое состояние и не влияет на профиль, награды или рейтинг.
5. Опубликовать новую версию для обучения. Проверка продолжает использовать закреплённую версию 1, начатые попытки остаются на своей версии. Повтор публикации не создаёт ещё одну версию.

Текущий движок поддерживает два вида смен. Редактор сохраняет их набор критериев и правила появления багажа, просрочки и зачёта. Создание произвольных видов событий, изменение формулы оценки и редактор коротких упражнений в этот этап не входят. Проверка структуры не заменяет предметное согласование и проверку всех учебных исходов человеком.

Запись черновика требует ожидаемую ревизию. При конфликте изменения пользователя остаются в форме; загрузка сохранённой версии выполняется отдельной кнопкой. Опубликованный черновик нельзя редактировать: нужно создать следующую копию. Публикации из интерфейса и команды выполняются под общей блокировкой каталога. Новые таблицы не изменяют прежние результаты; откат к предыдущему приложению оставляет таблицы редактора в базе.

Проверки: доступ и его отзыв; CSRF и чужой черновик; неверные ссылки и циклы без выхода; параллельное редактирование; повтор публикации; сохранность старой попытки; новая версия только в обучении; проба без начислений; сохранение после перезагрузки; создание ветки, проба, публикация и открытие её в игре; малый экран и клавиатура. После проверки — GitHub, локальный Docker и Aeza, с резервной копией удалённой базы перед миграцией.


## Контракт и сохранение данных

Адрес интерфейса: `/#editor`; локально `http://127.0.0.1:8180/#editor`. Код задаёт владелец через `EDITOR_ACCESS_CODE` в `.env`; скрипт запуска создаёт случайный код один раз. Смена кода требует пересоздания API и сразу отменяет выданный доступ. Общее право методиста подходит для демонстрации. Личные учётные записи и согласование публикации вторым сотрудником пока отсутствуют.

`GET /api/v1/editor` возвращает опубликованные версии и черновики текущего профиля. `POST /editor/drafts` принимает `request_id`, `scenario`, `version`; повтор с тем же идентификатором возвращает существующий черновик. `PUT /editor/drafts/{id}` принимает `expected_revision` и строку `definition` с JSON. При устаревшей редакции возвращается 409; прежняя запись сохраняется. Черновик после неоднозначного сетевого сбоя нужно загрузить заново, предварительно скопировав несохранённые правки.

`POST /editor/drafts/{id}/publish` публикует сохранённую редакцию. `POST /editor/drafts/{id}/preview` создаёт пробное прохождение и заменяет предыдущую пробу автора. Команды пробы используют `request_id` и `expected_revision`. Проба замораживает содержание на момент старта; последующие изменения черновика в неё не попадают. Возврат к черновику не ставит пробу на паузу. После перезагрузки можно начать новую пробу. Фоновый обработчик не обходит авторские пробы: их абсолютные сроки проверяются при обращении к ним.

Пределы: 150 КБ содержания, 40 шагов, 12 действий на шаг, 3000 исследуемых сочетаний. Достижимость проверяется без давления времени; проверка не доказывает наличие зачётного исхода и не проверяет смысл реплик. При публикации автор должен самостоятельно пройти правильные и ошибочные ветки. Ограничения редактора не меняют неизменяемые исходные сценарии версии 1.

Перед обновлением сервера сохраняется база PostgreSQL. Миграция только добавляет таблицы. Для отката к старому коду дополнительные таблицы оставляются на месте: команда обратной миграции специально не удаляет авторские данные.
